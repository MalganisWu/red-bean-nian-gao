# 交互与无障碍

本文描述行为契约，不擅自改变已确认的视觉样式。需要调整 focus 外观、对比度或组件几何时，先在 Preview 中评审。

## 键盘与焦点

- 所有按钮、链接、输入、菜单项、折叠控制和单选项必须能用键盘到达。
- 使用 `:focus-visible`，焦点不能只靠颜色细微变化表达，也不能被 `overflow` 裁切。
- 复合控件使用符合语义的键盘模型：菜单支持方向键与 Escape；单选组使用方向键；折叠控件用 Enter / Space。
- 打开浮层后焦点进入可操作内容；关闭后回到触发器。页面切换后的焦点落在主标题或主内容起点。

## 命中区与文字

- 主要触控目标最小为 44 × 44px；紧凑桌面控件可以视觉更小，但需要扩展可点击区域。
- 正文和必要元信息不低于 12px。10px 只允许非必要装饰，不承载状态、时间或操作结果。
- 长路径、URL、命令与连续字符必须在容器内换行或局部滚动，不得撑破页面。
- 文本、边界和 focus 对比度应满足 WCAG 2.2 AA；最终色值变化先走 Preview。

## 状态与反馈

- 成功绿只表示成功，鲜红只表示失败或破坏性结果；必须同时出现文字或图标。
- 豆沙红表示品牌、选择、focus 与确认动作，不表示错误或任务健康度。
- Loading 使用明确文本或 `aria-busy`；完成、失败、复制结果等动态反馈使用合适的 live region。
- Disabled 与 loading 不混用：disabled 说明不可操作，loading 说明操作已接收且正在进行。
- 尊重 `prefers-reduced-motion`；呼吸点和过渡在减弱动效模式下停止或改为静态状态。
- hover 与 active 只改变颜色、边框或背景，不改变元素几何位置（位移、缩放、尺寸）。

## 内容与隐私

- 图标按钮必须有可读名称；装饰图标使用 `aria-hidden="true"`。
- Account 示例只使用虚构身份：张三、`san.zhang`、`san.zhang@example.com`。
- 错误信息描述发生了什么和下一步动作，不暴露 token、绝对本机路径、密钥或内部堆栈。
- Process 展示可验证进展，不声称展示模型原始思维。

## 必测路径

每个交互组件至少检查：键盘顺序、可见焦点、200% 缩放、360px 宽度、Light / Dark、减弱动效、屏幕阅读器名称以及异步状态切换。
