# 视觉评审统一量表

两名专家独立使用同一张量表。每项给出整数分及一至三条证据；总分是决策辅助，不能覆盖 P0 问题。

| 维度 | 满分 | 评审重点 |
| --- | ---: | --- |
| 视觉层级与可读性 | 20 | 注意力顺序、文字层级、密度、留白、扫读效率 |
| Token 与组件一致性 | 20 | 权威 token、组件语法、间距和状态表达是否一致 |
| 交互与状态清晰度 | 20 | 可发现性、操作反馈、加载/空/错误/完成状态、连续性 |
| Light/Dark 对等性 | 15 | 两种主题的对比度、角色映射、信息层级和视觉重量 |
| 无障碍与响应式 | 15 | 非颜色线索、焦点、可读尺寸、键盘路径、窄屏适配 |
| 产品连续性与实现成本 | 10 | 与现有产品一致、复用真实组件、改动范围和维护成本 |
| **总计** | **100** | 先检查阻断项，再参考总分 |

## 分数解释

- 90–100：可以进入实现或验收，仅有轻微润色项。
- 80–89：方向成立，处理明确问题后进入实现。
- 70–79：需要修改关键设计后重新评审。
- 70 以下：核心层级、交互或系统一致性不足，应重新设计。

两位专家总分相差超过 10 分，或同一维度出现方向性判断冲突时，必须保留双方证据并由主 Agent 说明取舍，不直接平均消除分歧。

## 问题优先级

- **P0 阻断**：导致关键任务不可完成、状态含义错误、严重无障碍问题，或破坏权威 token/组件单一来源。
- **P1 重要**：显著影响理解、发现、效率、跨主题一致性或新功能验收。
- **P2 润色**：不阻碍任务，但会改善节奏、精致度或局部一致性。

## 每条发现必须包含

1. 位置：页面、组件、状态、主题和视口；可定位时给出源码路径。
2. 事实：当前实际看到什么，不把个人偏好写成事实。
3. 影响：它如何影响理解、操作、一致性或可访问性。
4. 依据：对应的权威设计规则或可观察证据。
5. 建议：最小可执行改法及验证方式。

没有真实界面证据的推测必须标为“待验证”，不得计为已确认缺陷。
