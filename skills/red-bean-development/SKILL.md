# red-bean-nian-gao 开发工作流

本 Skill 是跨客户端的工作流入口，不是规范副本。`AGENTS.md` 是唯一事实来源；不得把其中的架构、编码、测试或交付规则复制到本文件。

## 开始任务

1. 用 `git rev-parse --show-toplevel` 确认当前仓库根目录。不要依赖固定绝对路径。
2. 完整读取仓库根目录的 `AGENTS.md`。
3. 根据将要读取或修改的路径，完整读取沿途适用的模块级 `AGENTS.md`。规则冲突时，以离目标文件最近的文件为准。
4. 按 `AGENTS.md` 的路由读取它直接要求的规范或契约；不要预先加载无关文档。
5. 检查工作区状态，保留用户已有改动。范围或权限不明确时先确认。

如果当前工作目录不在目标仓库内，先定位用户指定的仓库；不能因此假定仓库中的 `AGENTS.md` 已被客户端自动加载。

## 执行任务

- 严格执行已加载 `AGENTS.md` 中的开发流程、模块边界、测试和提交规则。
- 编写行为实现前先确定测试层级与验收条件；适用 TDD 时先运行失败测试并确认它因目标行为缺失而失败。符合规范中的豁免场景时，记录原因和替代验证。
- 先确定改动的真实来源与消费方；共享组件、契约或 token 不建立第二份实现。
- 只做用户授权范围内的修改。提交、推送、部署或其他外部写入仍需用户已有授权。

## 文档影响审查

执行适用 `AGENTS.md` 中的“文档影响门禁”，从 `docs/README.md` 路由到与本次 diff 有关的权威
活文档。不要在 Skill 中维护第二份“改动类型 → 文档”映射，也不要用修改冻结记录代替同步当前事实。
每一类相关文档都必须得出“已更新”或“无需更新”的结论。

## 验证与交付

1. 运行 `make docs-check`，再运行适用 `AGENTS.md` 指定的最小定向检查和最终交付门禁。`docs-check` 通过不能替代上面的语义审查。
2. 确认 `git diff --check` 通过，并复查最终文件清单没有遗漏文档或混入无关改动。
3. 仅在用户已授权时提交和同步远端；同步后核对本地与远端 revision，以及用户实际访问的服务或页面。
4. 最终报告实现结果、测试先行证据（先失败后通过，或豁免理由）、验证结果、提交与远端状态。单列“文档影响”，逐项写明 `docs/README.md` 及其相关链接目标、`AGENTS.md`、项目 README 和设计/契约文档是“已更新”还是“无需更新（理由）”。不要把“本地已修改”表述为“远端已更新”。
