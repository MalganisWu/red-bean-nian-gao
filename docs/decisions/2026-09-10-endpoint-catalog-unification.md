# 决策：路由路径单一事实来源（API_ROUTES 命名表）

状态：已接受
日期：2026-09-10

背景：接口路径存在三份手写清单（契约 `API_ROUTES` / `API_PATHS`、后端 `*.routes.ts` 字面量、
前端调用常量），无机械对账；已发生目录自创记法 `*key` 与真实 Fastify 通配 `*` 不一致的漂移，
后端加端点忘写目录时前端与文档静默失真。

选项：
- 彻底版：路径只写在契约命名表一处，后端 `bindRoute`、前端 `buildPath` 取用。
- 单向约束版：路径照写 + `RoutePath` 联合类型编译期校验（仍是两份手写）。
- 维持现状 + 对账测试。

决策：彻底版。`API_ROUTES` 命名表（30 条）+ `bindRoute`（method/path 取自命名表，`authenticated`
与 `auth` 钩子启动断言）+ `buildPath`（前端模板渲染）+ `scripts/check-route-collisions.mjs`
（静态/参数段同深度共存与重复注册的机械门禁）。

理由：三份清单中只有彻底版把"维护份数"降到 1。单向约束版表面安全但“路径写两份”的认知负担
仍在；对账测试只能事后发现不能事前防止。`bindRoute` 的启动断言顺带补上了“类型管不到行为”
的空缺（`authenticated=true` 缺认证钩子即启动失败）。

后果：
- 契约包成为后端运行时依赖；路径改名 = 前后端原子变更（目录一处改动两端同步）。
- 路由文件不再出现路径字面量，直观感用"命名常量 + 链路指纹注释"补偿。
- 模板语法限定 Fastify 原生（`:param`、`*`）；`{xxx}` 仅允许出现在文档展示投影。
- 后续新增接口的流程：契约命名表 → bindRoute 注册 → 前端 buildPath 调用 → 契约测试同步。
