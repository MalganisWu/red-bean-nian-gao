# 决策：注释治理（放宽翻译式注释，收紧失真红线，新增决策备忘录）

状态：已接受
日期：2026-09-10

背景：对照 claude-code / Hermes 源码，本仓业务方法注释密度偏低——公开方法大多只有方法名，
并发与一致性敏感点（fencing/revision/CAS）注释不全；同时已有规范对方法内注释给出了
过严的排除清单，实际效果是"不敢写"而非"写得好"。

选项：
- 严格白名单：方法内注释只允许"意图、不变量、分支依据"三类，翻译式注释禁止。
- 宽松准入（选定）：意图/取舍/不变量/分支依据为最高价值；翻译式注释允许但低价值；
  唯一红线是注释与代码不一致（失真）。
- 硬性要求：业务应用服务公开方法必须有职责注释（做什么、边界、何时抛错）。

决策：宽松准入 + 最低义务 + 单一红线。理由：本仓主要矛盾是"注释过少"而非"注释噪音"，
严格排除清单只会让沉默者更沉默；失真注释（代码改了注释没改）才是真正有害的注释。

后果：
- AGENTS.md 注释规范段重写：公开方法职责注释为义务；方法体注释无排除清单；
  `// ── 阶段名 ──` 分段标题为推荐；注释必须与代码同 diff 更新并在评审时必查。
- 新增 `docs/decisions/`（本目录）：跨任务决策的"为什么"独立于 spec/plan 冻结记录，
  只追加不修改；代码注释只承载局部"为什么"。
- 第一个试点模块为 task 模块（agent 模块因并行重构暂缓），按新标准补注释并作为全仓样板。
