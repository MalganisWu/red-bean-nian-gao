# 会话轨迹视图

> 文档性质：活文档。描述会话轨迹（Trajectory）只读审计视图的领域模型、信息架构、视觉定稿与数据需求。
> 视觉定稿已入册为 Design System 组件：`TrajectoryTimeline`（泳道时序概览，含区域选择与缩放）、
> `TrajectoryLedger`（轮次记录表，含记录序号、请求分组、轮次结束标记、压缩状态）、
> `TrajectoryInspector`（记录检查器，**覆盖式窗格**，含请求详情）与共享纯数据模型 `trajectoryTypes.ts`；
> Showcase 页为「会话轨迹 · Trajectory」。探索期 mock 在 `scratch/`（未入库）。

## 定位

会话轨迹是 Session 的**只读审计视图**，回答三个问题：每一轮 Agent 做了什么、调了哪些工具、
各花了多少 token 和时间。入口是 ChatPage 的会话内子视图（`SessionView` 增加 `'trajectory'`），
不改变会话 URL 形态。流式进行中实时渲染：与 chat 共享同一批 SSE 事件做第二个投影
（一条事件流、两个独立投影），进行中的记录只显示开始标记、不虚构耗时；记录表跟随尾部
直到用户上滚（距底部超过 40px 暂停跟随，回到底部附近自动恢复，流式结束后下一轮重新跟随）；
live 耗时是客户端近似值，持久化数字以服务端为准。

## 领域模型（2026-09-15 修订）

层级是 **轮次 → 请求 → 产出**，并且 **不是树，而是交替的阶段序列**：

```
轮次 1                                  ← 一次用户提问 → Agent 回复完毕，含多个请求
  请求 1                                ← 一次模型网关调用
    产出：思考 / 正文 / 工具调用          ← 模型生成的内容
  ﹝系统﹞工具执行                        ← 独立阶段，与请求平级
  请求 2
    产出：思考 / 正文
  ﹝系统﹞工具执行
  请求 3
    产出：正文
```

- **轮次**：一次用户提问到 Agent 回复完毕，**含多个请求**。标题行承载本轮合计（请求数、工具数、
  失败数、入·出·缓三段 token、总耗时）。
- **请求**：**一次模型网关调用**。行内显示请求序号、模型、尝试序（如 `2/3`）、入·出 token 与耗时。
  `attempts` 是它的**重试明细**，**不单独成层**。
- **产出**：这一次响应**生成**的内容——**思考（reasoning）/ 正文（content）/ 工具调用（tool-call）**。
  三者**都是模型写出的字符串**，都计入该请求的**输出 token**。一次响应里出现哪几块、以什么顺序，
  **取决于网关怎么返回**，不是固定组合。
- **系统执行**（工具执行 / 子 Agent 委派）：**独立阶段，与请求平级，不在请求之下**。它不是模型生成，
  **不产出模型 token**，但有耗时。

### 工具调用 ≠ 工具执行

**两者渲染成两行**，因为性质不同：

- **工具调用**是模型写出的**原始字符串**（`web_search(红豆年糕 传统做法)`），属于**请求的产出**，
  消耗该请求的输出 token；
- **工具执行**是**系统阶段**（`web_search → 5 条结果 · 1.8s`），不消耗模型 token，有独立的耗时与结果。

### 请求输入的累积关系

**请求 N 的输入 = 请求 N−1 的输入 + 请求 N−1 的输出 + 工具结果的 token。**

不单独引入「上下文」实体——**每一次最新请求看见的就是最新的上下文**。
各请求的输入 token 可直接体现这个累积（后一次总不小于前一次）。

### token 归属

| 阶段 | 谁产生 | 计入 |
| --- | --- | --- |
| 思考 / 正文 / 工具调用 | 模型 | **本请求的输出** |
| 工具执行 | 系统 | **不计入模型 token**（有耗时） |
| 工具结果 | 系统 | **不计入模型 token**（是「新产出的内容」，进入下一次请求的输入） |

- **输出 token 不拆分到各块产出**：Provider 只返回整次响应的总量，不返回按块拆分。
- **工具结果的 token 数不可得**：事实日志不记录该数字，因此界面**不显示**它；累积关系只能通过
  「下一次请求的输入变大」间接看出。
- `call.tokens` 的口径是**最后一次 attempt 的用量**，不是各次重试之和；重试时看检查器里的尝试明细。

### 数据形态

数据层仍是**扁平的 append-only 事实日志**（`records[]` + `kind`）。上面的分组与层级
**在渲染层按位置推导**（`call` 开启一个请求，其后紧跟的 `tool`/`subagent` 归属它），
**不走嵌套契约**——嵌套会强行把「独立阶段」塞成请求的子项，与模型冲突。

## 信息架构

三层结构，自上而下：

1. **页头统计**：会话累计 token、活动耗时、会话跨度（三件指标卡）。
2. **泳道时序概览**：用户 / 工具 / LLM 调用 / 压缩四条泳道；段的位置与宽度 ∝ 真实时刻与耗时，
   超过 2 s 的空档折叠为窄缝；失败段就地红色显示在所属泳道；子 Agent 是工具泳道内的空心段；
   时序 / 序列双模式切换；点击段定位并选中下方对应记录。
   **区域选择**：在泳道上拖选一个时间区间，记录表聚焦到该闭区间内任何时刻处于活动的记录
   （区间外记录淡隐，泳道上选中区间高亮）；滚轮缩放时间域，右键单击清除选择，
   右键拖动平移视口，Esc 复位。
3. **轮次分组记录表**：七列网格「# | 时刻 | 时间轴 | 记录 | token 入·出·缓 | 耗时条 | 时长」，
   外加一个**覆盖式详情窗格**（见下）。
   轮次标题行承载本轮合计；轮次间空档以虚线 + pill 标签标注间隔与起止时刻
   （虚线只画在「记录」列内，不是整行通宽）；压缩事件是表内一等公民卡片（虚线描边 +
   压缩前后 token 对照条）。
   **列优先级**：容器查询阈值 760px（≈ 宽模板固定列 500px + 间隙 60px + 「记录」列 180px 可读下限）。
   低于阈值时让出「耗时条」列——它只是「时长」数字的重复表达——并把 token 列收窄为「入 · 出」
   （「缓」在窄列里只会被截成省略号，完整值由检查器承载），保证最重要的「记录」列仍有 180px 下限；
   不做横向滚动。

### 详情窗格（覆盖式）

记录检查器是**覆盖式右窗格**，**不是挤压式常驻栏**：绝对定位在表格容器右侧，**表格宽度不受影响**
——挤压式会让「记录」列从 298px 掉到 180px，并在窄处造成整表横向溢出 20px。

- 宽度 `clamp(320px, 38%, 440px)`，并用 `max-width: calc(100% - 280px)` 保证表格永远留 ≥280px 可读宽。
- 形态是**贴边窗格**：顶部贴容器、无圆角、**无投影**，边界只由 1px 左边框承担——它是「贴在右侧的
  一块面」，不是浮空卡片。代价是面板盖住右侧的 token / 耗时条 / 时长三列，关闭即恢复。
- 结构：头 42px、tabs 34px（选中下划线 2px、左右各缩进 9px）、关闭键 28×28 圆角 6px。
- 按记录类型分 tab：用户（完整消息）、请求 / 调用（思考 / 正文 / 概览含模型与入·出·缓存 /
  **尝试明细含重试原因**）、工具（参数 / 结果 / 概览）、子 Agent（概览含 token 与耗时 / 结果）、
  压缩（前后对照与策略说明）。
- **点产出行直接停到对应 tab**：点「正文」就停在正文，而不是默认的「思考」。

### 折叠

三层折叠，**默认全展开**：

| 层级 | 可折叠条件 | 折叠后 |
| --- | --- | --- |
| 轮次 | 轮内「非即时、非系统执行」的记录 > 1 条 | 插入 **20px 摘要行**：`… N 个请求 · 工具 ×M` |
| 请求 | 该请求后紧跟工具执行 | 插入一行：`… N 个工具调用 · name1, name2` |

- 触发：点轮次标题 / 点摘要行展开 / **双击轮内任意行折叠该轮**；工具栏有「折叠全部 / 展开全部」。
- 摘要行占「记录」列，右侧 5 个数字列留空——否则七列会错位。

### 终态标记

**轮次结束标记（turn-end）**：每轮**收尾后**在尾部落一条轻量结束记录，显示轮次终态与备注；
失败轮次的记录表尾部必须有据可查，不允许「悄悄烂尾」。
**尚未终结的轮次没有结束标记**，而是在轮次标题行显示中性「进行中」chip——没有终态就不显示终态。
会话结束（session-end）在尾部同样落一条标记，且只在没有运行中的 run 时渲染（详见「进行中语义」）。

终态值**按触发者区分**，四个近义值不得混用：`completed` / `failed` / `cancelled`（用户取消）/
`exhausted` / **`interrupt`**（LLM 主动发起挂起，展示为「等待用户」）/ **`crashed`**（进程崩溃遗留，
展示为「已中断」）。wire 只带机制值，展示文案在前端映射。

**记录状态**同理：`success` / `error` / `interrupt`（等审批）/ `incomplete`（用户打断、没有结果）。

### 记录序号

每条记录带稳定 `#N` 序号（全局递增，不受折叠与过滤影响），供跨记录引用与后续从聊天消息卡片
深链定位到轨迹记录。

### 压缩的多状态

压缩记录除成功外还必须覆盖 `进行中 / 失败 / 已中断` 三态
（压缩失败时上下文未收缩，后续请求的输入 token 会异常跳涨，轨迹必须能看出）。

压缩作为会话级事实并入 `session_runs.facts` 序列，**不单开列**：独立列需贯穿 session 生命周期
CAS 写入并新开一条版本纪律通道，而并入事实序列零迁移、复用 append 追加与 ignorable 版本纪律。

## 视觉定稿（v3）

- **配色**：用户=豆沙红（身份色）、LLM 调用=中性灰、工具=石板蓝、子 Agent=灰绿、压缩=暖石灰、
  失败=既有状态红；分类色只落在 chip、节点、细条等小面积元素，正文摘要恒为中性色。
- **chip**：统一 **19px 高、左右 5px、字重 600、字距 0.035em**、圆角 8px。**所有身份 chip 尺寸一致**
  （曾出现终态 chip 24px、身份 chip 20px 的不一致，根因是 `cn()` 里 tailwind-merge 把自定义字号
  `text-label` 误判为文字颜色而静默丢弃——已在 `cn()` 登记自定义字号根治）。
- **行高**：数据行统一 **30px**；轮次标题行 42px；折叠摘要行 20px。
- **分隔线**：行分隔用 `--border` 的 **40% 透明度**；表头底线保持
  `--border`（比行分隔重一档）。窄容器不承诺「缓」。
- **表头**：字重 500；底色比表体低一档。
- **选中**：行底 `--primary-soft` + 左侧 **3px** 品牌竖条（独立于轮次导轨）。
- **轮次**：标题行有填充带；除第一轮外，轮次起点画一条 **2px、骑在行边界上、贯通整行** 的细线。
- **条形语言**统一为全圆角胶囊；耗时条与泳道段同形。
- **暗色对等**：空心元素（子 Agent 条/段/chip、压缩胶囊）的填充为分类色低透明度混合，避免近黑
  背景上读作「黑洞」；压缩卡片使用 elevated muted 面。
- **空档带**不做纹理，纯留白 + 虚线 + pill；进行中记录只显示开始标记，不虚构耗时。

## 交互

- **选中是幂等的**：点一行就选中它并打开详情窗格，**再点不会取消**。关闭只有三条路径：
  点 ✕、按 Esc、点表格空白处。（曾经的「按 tab 是否 undefined 决定要不要 toggle」导致
  「有时灵有时不灵」，已废弃。）
- **选中解析必须在「展示轮次」上做**（历史 + 实时）：流式进行中实时轮次不在持久化视图里，
  只查持久化视图会让**点击任何一行都打不开面板**。
- **行 `:focus-visible`** 用**内嵌环**（`inset 0 0 0 1px`），不是 outline——行是 30px 全宽，
  `outline-offset` 会溢出到相邻行。
- **Esc 必须加输入框守卫**：面板的 Esc 监听挂在 `window` 上时，在搜索框里按 Esc 会误关面板。
- **检查器 tabs** 用 `role="tablist"` / `role="tab" aria-selected` / `role="tabpanel"`，支持 ←/→ 切换；
  **tab 跨记录记忆**：切到「概览」后点别的记录仍停在「概览」。
- **行 hover 有 120ms 过渡**（6 处行容器都要加，漏一处动效不一致）。
- **数据行 `cursor: default`**（靠 hover 底色 + 选中竖条传达可点）；折叠摘要行与轮次标题保持 `pointer`。
- 搜索过滤、轮次折叠与全部折叠、泳道与记录选中态联动。

## 进行中语义（未终结轮次与双投影合并）

运行中的 run 在 `session_runs` 里就是 `status='running'` 的一行，**它不是终态**。投影与渲染遵守：

- **后端投影**：`running` 且在本进程启动之后开始的 run → 该轮不带 `endState`（wire 为 `null`），
  会话 `sessionEnd` 同样为 `null`；轮次时长退化为「已落库活动区间」的下界，不是最终耗时。
- **崩溃遗留**：`running` 但早于本次进程启动开始的 run（进程已重启，不可能还在执行）才算崩溃遗留，
  按 **`crashed`** 收尾并附注「运行进程中断」。进程启动时刻（`shared/lifecycle/process-start.ts`）
  是单进程部署下的确定性判据，不用心跳或超时猜测。
- **挂起等待用户**：`status='interrupted'` 是 Runtime `suspended` 的唯一落点，语义是
  **「LLM 发起挂起、等用户作答」**（模型调用了 interrupting 工具），映射为终态 **`interrupt`**，
  展示为「等待用户」。它与崩溃遗留的 `crashed` 只差一个字母，**不得混用**。
- **空事实 run**：没有任何事实的 run（启动即失败）不属于任何轮次，也不得改写上一轮的终态；
  会话终态仍取最后一个 run——失败确实发生过，审计不掩盖。
- **双投影合并**：历史投影里「最后一轮若尚未终结」，它就是正在流式的同一个 run（run 容器在运行开始
  即落库），必须由实时投影的轮次**取代**，不能并排——否则同一个 run 会出现两个同号轮次。
  实时轮次号与记录 `#N` 都续接已终结的历史投影（`trajectory-store.alignToHistory`）。
- **实时侧只保留当前进行中的一轮**：已结束的轮次一律以持久化历史为准，实时侧不累积。
- **实时轮次摘要与持久化同口径**：有回答内容时取回答首行，否则回落到思考首行
  （与后端 `#assistantRecord` 一致，上限 `SUMMARY_MAX_CHARS = 200`）。作答期间记录行文本必须跟着
  回答增长——只更新 `reply` 会让整段作答里记录行一动不动，看起来像轨迹停住了。
- **流式结束即重拉**：中途取到的历史快照必然缺少终态、token 与请求子记录，DONE / ERROR 后必须重新
  拉取持久化数据，页面不得停在「没有结束标记」的中间态。Runtime 侧保证 run 终态与事实先落库、
  再发 DONE（`default-agent-run-service` 的 `facts.finalize` 早于 `handle.publish`），
  因此 DONE 后的重拉必定能取到本轮。
- **五条流结束路径都要收尾实时行**（DONE / ERROR / 网络错误 / onClose / cancel）：把仍处于
  `running` 的记录收成 `incomplete`。与 chat 投影的 `settleIncompleteTools` 同址——SSE 上不存在
  「用户刚打断了自己」的服务端事件（取消由客户端 abort 连接发起），不主动收尾会让终态页面
  永久显示「正在执行」。
- **交接判据是「位置」而不是「时刻」**：「正在流式」与「有实时轮次可展示」是两个独立状态：前者只驱动
  跟随尾部、跳秒与隐藏会话终态，后者在流结束后仍然成立。每次成功读取持久化轨迹后按
  **已终结轮次数 ≥ 实时轮次号** 判定该 run 是否已经落库：成立就当场丢弃实时轮次（同一批更新
  里完成，不存在「实时已撤、历史未到」的空窗），不成立就保留实时轮次。
  这个判据不依赖 DONE 是否到达，因此流被中止、DONE 丢失或长驻页面实例不一致时，也不会出现
  同一轮并列两条；**重拉失败保留实时轮次**——内存里的实时投影是真实数据，比旧快照或空态更可信，
  此时也不因为一次取数失败就把记录表换成报错页。
- **store 不做热替换（开发期）**：Vite 的 React Fast Refresh 只重建「接受更新」的组件边界，
  未被重建的模块（如 `useChatStream`）会继续持有旧 store 实例，写入方与读取方因此各绑一份 state
  （表现：实时投影不再跟随 SSE、结束后出现重复轮次，刷新即恢复）。四个 store 模块都声明自接受
  并整页刷新，保证开发期实例唯一。

## 已知缺口（明确记录，不静默）

| 缺口 | 性质 | 现状 |
| --- | --- | --- |
| **搜索过滤不生效** | **缺失功能**（不是 bug） | `data-hidden` 属性全仓只有写入、没有读取消费者，搜索框输什么都不会过滤。要做需在**投影层过滤并重算分组**（不能只加 `[data-hidden]{display:none}`，那会留下孤立的轮次底色与错位轴线），且**搜索优先于折叠**。 |
| **首 token（TTFT）** | **数据不可得** | 全仓无 `firstToken` / `ttft`；`RunAssistantFact` 只有 `at` / `durationMs` / `usage` / `attempts[]`。要显示需先改 Runtime 采集 + 契约。**界面不显示，不编数。** |
| **工具结果的 token 数** | **数据不可得** | 事实日志不记录。同上，不显示。 |
| **面板可拖拽调宽** | **缺失功能** | 需 `role="separator"` + ←/→ 步进 + 双击复位；当前只做固定 `clamp`。 |
| **轮次填充带的暗色强度** | 有意近似 | 目标值 Light 1.16:1 / Dark 1.64:1（两套不对称），没有任何现有 token 能同时命中两套；我们用 `--muted`（Light 1.10 / Dark 1.17），**暗色下偏弱**。逐值对齐需新增 `.dark` 下换值的 token。 |

## 非目标

- **两列表格**：会丢掉「耗时条一眼看出哪次请求最久」；我们保留七列；
- **把「工具调用」与「工具执行」合并成一行**：会推翻领域模型（模型产出 vs 系统执行，性质不同）；
- 琥珀/紫蓝配色、8px 与 10px 字号、2/3/4/5px 圆角、多档阴影、0.5px 线：与设计系统硬约束冲突。
